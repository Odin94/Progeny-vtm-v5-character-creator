# Performance coverage across every view

Baseline for this pass: `3d9ee75cb02a7462eeb1523eca3056ea38ed61e8`. After: the implementation commit containing this report. The previous sheet investigation remains in [2026-10-03.md](./2026-10-03.md). Both revisions use Node 24.15.0, pnpm 10.33.0, identical lockfiles, and the same Apple M5 machine.

The Vercel skill is applied with rendering/rerendering CRITICAL. Changes defer the creator from common startup and the account PDF exporter until export, isolate unchanged creator/coterie/homebrew sections, keep account nickname drafts inside the profile form, debounce library/admin searches by 200ms, and aggregate library statistics once per request. No persistent data cache, database migration, schema change, or backend authorization change is introduced.

These are React development Profiler durations in jsdom, with real Mantine views and controls; they exclude browser layout/paint and are not input-latency or FCP claims. Three matched runs were interleaved before/after, with no overlapping benchmark execution. Other concurrent work on the machine makes durations noisy; raw samples include every run. Fixtures replace networking/auth/navigation, while mounted sections, state and input handlers are real. The profile form harness mounts the same sibling profile/list composition used by the account page; its baseline-only draft props are ignored by the new form. Counts and bundle bytes are stronger evidence than wall-clock timings.

The backend benchmark builds the actual Fastify app, schema fixtures and SQLite `:memory:` database; it measures validation, queries, aggregation and response serialization through `app.inject`. It seeds 150 publications and 15,000 each ratings/copies/comments, does three warm-up requests and seven samples of three requests, and checks response counts and stability on every request. Existing rate limits remain enabled; only 24 requests are made. This is a substantial synthetic library, not production load or external network latency.

## Reproduce and validate

From the frontend directory, run `pnpm exec vitest run benchmarks/allViews.test.tsx` against both source revisions, interleaving runs. Build with `pnpm exec vite build --manifest` (no telemetry upload) and run `node scripts/benchmarkRoutes.mjs build`. From backend, run `pnpm exec tsx scripts/benchmarkLibrary.ts`; the script forcibly selects a disposable in-memory database before imports, uses fixture credentials, and exits after closing its own test app.

For native production previews, generate a validated fixture with `PERF_FIXTURE_OUTPUT=../../progeny-allviews-fixture.json pnpm exec vitest run benchmarks/fixture.test.ts` from frontend. Then from the repository root run `node frontend/scripts/performancePreview.mjs frontend/build 5341 ../progeny-allviews-fixture.json`; repeat with retained baseline build on 5351. Open each path in native preview. All REST requests are redirected to the local fixture server; WebSockets are restricted to its origin. Never use this server as an authentication or backend correctness substitute.

Verification: frontend formatting/lint/typecheck/production build, 74 frontend test files / 370 tests, backend formatting/lint/build, 13 backend files / 71 tests all pass. New regressions cover draft ownership, coterie member/vital refresh, and unequal per-entry library aggregates (including zero ratings, unpublished-entry exclusion from the prior, ranking and filters). Independent reviewer recommendations were implemented and re-reviewed until no valuable actionable source recommendations remained.
